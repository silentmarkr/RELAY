💾 Backup / Restore

Render's free tier has no persistent disk — allowed devices, unlocked features, and history are lost on every git push/redeploy, and everything is lost if you delete the service/domain. Download the backup periodically (especially after a new unlock/customer) and keep it somewhere safe.
The auto-download filename includes a date/time stamp (e.g. relaybackup07260130.json = July 26, 1:30 AM — your browser's LOCAL time), so each allow creates a new file instead of overwriting the last one. These stay in your Downloads folder as your backup history.

🚀 Publish a New Update (build + publish in one click — no Termux/curl required)

One button, two steps: (1) builds a fresh omnipos-client.zip from the latest code in your repo, and (2) immediately announces this new version/changelog to existing clients (they'll see it in their "Check for Update"). If the build fails, the version publish will NOT proceed.
If you fill in a Target Installation ID, the "update available" notice will go ONLY to that device — other clients won't see it until you clear the target or make the same version global (blank Target ID). Note: the actual zip file is still shared/single — this only targets who sees the notice, it's not a hard download block.
