💳 Cloud Backup Pricing
OmniPOS Unlock Relay — ground truth for pricing

This is the ONLY place Cloud Backup pricing lives. OmniPOS installations fetch it from GET /relay/pricing on their own (with a local fallback cache in case this RELAY is unreachable) — nothing about price is hardcoded in OmniPOS anymore. Changes here take effect for every installation the next time they refresh (usually within the hour). Looking to edit Pro Theme / Module pricing instead? That has its own separate Feature Pricing page.

There is no separate "maintenance fee" anymore — the Monthly/Yearly price of whichever tier (Basic/Standard/Pro) a client actually subscribed to, set above, IS what's shown as their maintenance & monitoring fee on the Cloud Backup cost-share widget, the tier picker, and the Client Cost Allocation page. Edit a tier's price above and it applies to every client currently on that tier.

Module Subscriptions

RBAC Management and Multi-Branch Dashboard are subscriptions too (converted from a one-time purchase) — flat monthly/yearly pricing, no tiers. A subscription that lapses stays working for a grace period before it locks — editable below in "Grace Periods & Data Retention".

⏳ Grace Periods & Data Retention

Two independent timers, on purpose — the consequences are not the same. The module grace period just delays a lock-out (no data loss). The Cloud Backup retention period ends in permanent deletion of a customer's backed-up data from Neon — a background job checks this every 24 hours and purges anything past the deadline automatically (toggle below). Both values are shown to OMNIPOS installations live via GET /relay/pricing, so the countdown customers see in-app always matches what's set here.

module subscriptions

Grace Period (RBAC / Multi-Branch / AI Assistant)

Allowed range: 0–60 days. No data loss risk — this only delays losing access to the module.

Data Retention Period

Allowed range: 7–365 days. ⚠️ Irreversible once the sweep runs — Lifetime and currently-active subscriptions are always skipped.

ℹ️ How the Cloud Backup control center works (read first)
One screen for the whole Cloud Backup system — read-only.
• Clients = every installation that has backup data or a Cloud Backup subscription (so “subscribed but never synced” also shows up).
• Health: ok nothing wrong · warn needs attention (near quota, overdue backup, restore-heavy, debt countdown, expired) · danger act now (over quota, long-silent, in debt past limit, retention due). The cut-offs are editable in 🎚️ Thresholds.
• MRR = recurring plan revenue of active, non-lifetime clients (monthly price, or yearly ÷ 12). Cost comes from the real Neon usage split per client (Client Cost Allocation), so margin is only shown when the Neon API is configured.
• Failures / blocked counters: failed syncs/restores live in memory since the last RELAY restart; blocked attempts come from the activity log (last 500 events of every type).
• Actions here: purge an expired backup, download a client's backup JSON, enter the actual Neon bill. Everything else (prices, retention days) is edited in the Plans & Pricing tab.
